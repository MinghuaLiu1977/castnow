# iOS 原生底层与 Web 修复记录 (2026-08-14)

本次针对 iOS 投屏应用中的核心痛点（卡顿、画面不显示、麦克风静音）以及 Web 端的一个闪退 Bug 进行了彻底重构与修复。

## 详细修复项

### 1. 彻底重构 iOS 摄像头捕获模块 (CameraCapture)
*   **问题背景**：以前为了实现界面上同时拥有本地预览和向网页推流，我们使用了手动拼装 `AVCaptureSession` 和强转帧数据的土办法。这导致主线程频繁被底层硬件读写阻塞（表现为点击勾选后卡死几秒），且硬编码的视频方向导致网页端偶尔绿屏或完全黑屏。
*   **重构方案**：删除了所有手写 `AVCaptureSession` 的垃圾代码，整体切换到了 WebRTC 官方专门深度优化的原生类 `RTCCameraVideoCapturer`。
*   **改进效果**：
    *   **极速秒开**：通过自带的底层异步队列拉起摄像头，主界面勾选即见画面，彻底告别阻塞卡死。
    *   **自适应转码与方向**：官方库会自动感知您的手机是横屏还是竖屏，并将苹果原本的 YUV 帧自动重组为网页端解码器兼容的标准流。同时锁定了最高 30 帧的采集率，让推流既清晰又非常流畅。

### 2. 修复 iOS 无法听到 Web 端语音的 Bug
*   **问题背景**：iOS 对于音频路由非常严格。因为之前我们只给 WebRTC 丢了麦克风采集的权限，并没有在 App 层面激活全局的“音频会话”（Audio Session），导致 WebRTC 虽然接收到了声音，但是全部送进了手机**顶部的听筒**甚至被系统静音。
*   **修复方案**：在 `WebRTCManager.swift` 中手动激活并接管了 `RTCAudioSession.sharedInstance()`。强制将 `Category` 设为 `playAndRecord`，并且将音频路由 (`overrideOutputAudioPort`) 锁死到 `.speaker`。
*   **改进效果**：现在不管是发起投屏还是画中画聊天，对方网页端传来的声音都会非常洪亮地从手机底部的大扬声器播放出来。

### 3. 修复 Web 端挂断闪退的 JS 报错
*   **问题背景**：当手机端主动切断投屏时，Web 端控制台会报出 `ReferenceError: resetApp is not defined` 的致命错误，导致网页白屏卡住。
*   **修复方案**：这是由于在 `App.vue` 中调用 `startReceiverPeer` 挂载生命周期回调时，漏传了最核心的页面重置方法 `resetApp` 造成的。已经在传参里加上了这个补丁。
*   **改进效果**：现在对方挂断时，接收端可以完美地弹窗提示并平滑退回输入配对码的首页了。
